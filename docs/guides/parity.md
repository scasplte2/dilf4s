# Protocol implementation parity: coverage and remaining gaps

This capability inventory began with the Scala, Rust and TypeScript implementations on `unify/base` at
`958dc34e`. The resolution notes below were checked again on 2026-11-09; other entries retain that audit context. Each row is one capability the specs define (an operation, an encoding,
a refusal family or a limit), or one section of a vector file in `shared/vectors`. Each cell gives the public entry
point, the test that runs it against the shared vectors, and any known difference. Gaps are marked **GAP-n** and
ranked in [section 8](#8-gaps-ranked-by-risk). `porting.md` says how a new language reaches every row.

Line numbers drift. When you change an area, re-check its cells. Java binds Scala and Python binds Rust;
Go independently implements the canonical core. The inventory below is not a claim of full Go protocol coverage.

## How to read the cells

**Status words.**
- **gated**: a test loads that vector file (or section) and checks every row against this language's code.
- **schema only**: the file decodes into the generated vector types and re-encodes losslessly, but nothing runs.
  That holds for all 16 files in all three languages
  (`lang/scala/core/src/test/scala/xyz/kd5ujc/models/VectorSchemasSuite.scala:54`, `rs/core/tests/vector_schemas.rs:67`,
  `ts/core/test/vector-schemas.test.ts:42`). It is not a behaviour gate, and no cell below counts it as one.
- **not gated**: implemented, but no shared vector checks it.
- **missing**: no implementation in that language.
- **n/a**: the spec puts the capability elsewhere, for the stated reason (for example, only the reference has a store).

**Paths.**
- `rs/…` is `lang/rust/…`, and `ts/…` is `lang/ts/packages/…`.
- Scala sources are written `<module>/m/<path>` for `<module>/src/main/scala/xyz/kd5ujc/<module>/<path>`, and
  `<module>/t/<path>` for the same under `src/test`. For example, `lang/scala/crypto/m/signing/Ed25519.scala` is
  `lang/scala/crypto/src/main/scala/xyz/kd5ujc/crypto/signing/Ed25519.scala`. Any other path is written in full.
- Specs are `docs/specs/<name>.md`, cited as `name.md §n`.

## 1. How each language is gated

| | Scala (reference) | Rust | TypeScript |
|---|---|---|---|
| Vector gate | Each file is generated by the reference. Its suite regenerates the file in memory and compares it byte for byte with the committed file, so one test covers every section. The Scala cells cite that test. | Each test parses the file with the SDK's own JSON parser, decodes it into its generated vector type (`rs/core/tests/common/mod.rs:22`), and runs every row. | The same, through `loadVectors` (`ts/core/test/vectors.ts:41`, and one per package). |
| Kind coverage | Each error type's cases are listed through the compiler (`Mirror.SumOf`); a kind with no row and no exemption fails. | Each generated kind enum's `ALL` must have a row. | A `Record` keyed by each generated kind union, so a new kind does not compile until it is listed. |
| Not regenerated | `sigma_v1.json` is Ergo's: each case is verified (`lang/scala/crypto/t/sigma/SigmaVectorsSuite.scala:21`). `sigma_dilf4s_v1.json` is our prover's, re-proved from its seeds (`:30`). `zk_jlvm_v1.json` is the SP1 guest's: each statement is recomputed (`lang/scala/jlvm/t/ZkJlvmVectorsSuite.scala:126`). | | |

**SP1 guest.** `rs/zk/host/tests/guest_matches_native.rs` runs families of cases inside an SP1 v6 guest (execute mode
only) and compares each with native Rust. The Rust cells below say "guest:" for what it covers. The guest is built
without the `sign` feature, so it never runs key derivation, VRF signing-key decoding, or KES generation, loading or
evolution (`conformance.md` §6).

## 8. Gaps, ranked by risk

Ranks:
1. **Consensus**: the node backends (Scala and Rust), or a proved run and a native one, can disagree.
2. **Client correctness**: an SDK can give a wrong or untyped answer, or a capability has no vector to hold ports to it.
3. **Ergonomics**: missing conveniences, stale docs, absent producers.

Between the node backends there is no rank-1 gap. On every vector row, Scala and Rust agree on value, error kind,
`op`, `cause`, gas and warning count. GAP-1 and GAP-12 are the only known places where the two could differ, and
neither is reachable within the spec's limits or the committed outcome.

The previously identified guest operation-coverage gap, GAP-17, is closed. The guest and native implementation
share Rust code except for SP1-patched cryptography; the guest coverage gate now checks every operation.
The guest still samples the corpus, so that gate does not establish exhaustive execution of every shared row.
